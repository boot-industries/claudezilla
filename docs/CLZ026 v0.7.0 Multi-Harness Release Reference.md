# CLZ026 v0.7.0 Multi-Harness Release Reference

**Version:** 0.7.0
**Date:** 2026-09-09
**Type:** Minor release (Multi-harness surface expansion + community PR #22 + contract hardening)
**Previous:** 0.6.9

---

## Summary

Claudezilla v0.7.0 ("the multi-harness release") expands Claudezilla from a Claude-Code-centric Firefox bridge into a unified browser automation engine supporting Oh My Pi (OMP), Hermes Agent, and Pi Agent alongside Claude Code. This release directly implements the architectural roadmap outlined in [[CLZ025 Community Review Findings for v0.7.0 Planning]], merges community PR #22 from `@axiomvx-source` to eliminate an asynchronous settings loading race on `firefox_evaluate`, resolves Issue #19 by forwarding page state parameters and introducing explicit truncation metadata, and incorporates the `CLAUDEZILLA_AGENT_TIMEOUT_MS` environment override (PR #21 / #20).

**Status as of this document:** Code and docs complete. AMO package build, unit tests, and git commits to `main` verified.

---

## 1. Multi-Harness Architecture & Surface Expansion

### 1.1 Tool Discovery Policy (Eager vs. Lazy)

- **Problem:** Claudezilla's tool gateway (`firefox_activate`) relies on dynamic MCP `notifications/tools/list_changed`. While Claude Code reloads tool definitions on notification, client harnesses such as Oh My Pi (OMP), Hermes Agent, and Pi Agent discover MCP tools once during process initialization. In these clients, only `firefox_activate` was discovered, rendering browser control tools invisible unless manually activated.
- **Solution:** Added a dual-mode tool discovery policy governed by `--all-tools`, `--tools all`, or `CLAUDEZILLA_TOOL_MODE=all`:
  - **Eager mode (`all`):** Exposes the full catalog of browser automation tools immediately on startup. `firefox_activate` is retained in the tool list as a compatible no-op returning already-active categories.
  - **Lazy mode (`lazy`):** Default for Claude Code, exposing only `firefox_activate` initially to conserve context window tokens (~6,400 tokens saved).
  - Precedence: CLI argument > `CLAUDEZILLA_TOOL_MODE` env var > default `lazy`.

### 1.2 Neutral Session & Focus Loop Scoping

- **Problem:** Loop state in the native host and MCP server previously keyed specifically on Claude Code's session conventions (`CLAUDE_CODE_SESSION_ID` and `--resume`), preventing clean loop isolation across different harnesses running concurrently on the same machine.
- **Solution:** Implemented `getSessionId()` in `mcp/server.js` with unambiguous candidate precedence:
  1. `--resume <id>` (Claude Code CLI resume parameter)
  2. `--session-id <id>` (generic harness CLI parameter)
  3. `CLAUDEZILLA_SESSION_ID` (explicit engine override)
  4. `OMP_SESSION_ID` (Oh My Pi harness)
  5. `PI_SESSION_ID` (Pi Agent harness)
  6. `HERMES_SESSION_ID` (Hermes Agent harness)
  7. `CLAUDE_CODE_SESSION_ID` (Claude Code environment variable)
  8. Fallback to `undefined` (which maps to `__default__` in host memory)
- Host in-memory loop states validate session strings (length ≤ 128, alphanumeric + `_-:.~`) to isolate focus loops without cross-session pollution.
- *Harness Loop Boundary:* Autonomous loop interception via process exit interception remains implemented via `plugin/hooks/stop-hook.sh` for Claude Code. In OMP, Hermes, and Pi, agents can query and manage loops via `firefox_start_loop`, `firefox_stop_loop`, and `firefox_loop_status`, but hook-driven autonomous execution requires harness-native event support.

### 1.3 Multi-Harness Installers

- Updated `install/install-macos.sh` and `install/install-linux.sh` to accept `--target <claude|omp|hermes|pi|all>` (default: `claude`).
- **Oh My Pi (OMP):** Safely merges `claudezilla` into `~/.omp/mcp.json` with args `[".../mcp/server.js", "--all-tools"]` and a `timeout` of 120,000 ms (reconciling OMP's 30s default with long-running browser operations).
- **Hermes Agent:** Emits verified configuration instructions for `~/.hermes/config.yaml` under `mcp_servers`.
- **Pi Agent:** Emits configuration instructions for `~/.pi/config.json`.
- All mergers preserve existing non-Claudezilla MCP server configurations.

## 2. Community PRs and Contract Hardening

### 2.1 PR #22 — Evaluate Settings Load Race

- **Author:** `@axiomvx-source` (AxiomVX)
- **Problem:** `firefox_evaluate` intermittently failed with "firefox_evaluate is disabled. Enable it from the Claudezilla popup" even when enabled in `browser.storage.local`. On initial tab attachment, `initVisuals()` launched `loadSettings()` asynchronously without awaiting it, while `evaluate()` executed synchronously in the same message turn and read default `settings.allowEvaluate = false`.
- **Resolution:** Wrapped settings loading in a memoized promise `ensureSettingsLoaded()`. `evaluate()` was made asynchronous and awaits this promise prior to checking the opt-in gate.
- **Verification:** Added `tests/content-evaluate-settings.test.mjs`, verifying in a VM harness that `evaluate()` reliably awaits artificial storage read delays before evaluating expressions.

### 2.2 Issue #19 — Page State Parameter Forwarding & Truncation Metadata

- **Problem:** `extension/background.js` invoked `getPageState` in tabs with `{}` as arguments, discarding user-supplied count parameters (`maxHeadings`, `maxLinks`, etc.). Furthermore, string fields were silently truncated to 100/50 characters without metadata or warning.
- **Resolution:**
  - `background.js` now unpacks and forwards count parameters to content scripts.
  - `content.js` returns explicit `truncated: true` and `rawLength` metadata on headings, links, buttons, inputs, and images exceeding length caps.
  - Password fields remain strictly masked as `'***'` without exposing raw string lengths.
- **Verification:** Added `tests/page-state-forwarding.test.mjs` verifying limit overrides, truncation flags, and password masking.

### 2.3 Issue #20 / PR #21 — Configurable Agent Timeout

- **Author:** `@braklo` (Branislav Klocok)
- **Problem:** Idle agents were reaped by the MCP server tab cleanup routine after 10 minutes, disrupting workflows where humans interact with web pages between tool invocations.
- **Resolution:** Supported `CLAUDEZILLA_AGENT_TIMEOUT_MS` environment variable to override `AGENT_TIMEOUT_MS`. Documented this as a configurable mitigation pending full heartbeat redesign. Corrected a stale "two minutes" comment in `extension/background.js` to 10 minutes.
