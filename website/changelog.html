New Features

v0.6.6 2026-06-15

Stability, security, and AMO compliance — no new MCP tools

Stability

  • fix
    Timer-leak fixes across host, MCP server, and extension Per-request setTimeout handles in host/index.js, mcp/server.js, and extension/background.js are now tracked and cleared on response routing, socket close, and timeout fire. Long-lived sessions no longer accumulate retained timers.
  • fix
    Shutdown races plugged MCP server cleanup interval is unref()'d, post-navigate setTimeout(handleConsent, 600) is tracked and cleared on shutdown, and clearInterval precedes await sendGoodbye so the cleanup loop can't race the goodbye round-trip.
  • fix
    unhandledRejection no longer kills the MCP server Previously called process.exit(1) on any unhandled promise rejection, ending the session if a single tool path missed a .catch(). Now logs and continues.
  • fix
    Inbound framing cap lowered to 10 MB Native-messaging max was 4 GB; lowered to match the MCP server's buffer limit, preventing huge buffer pre-allocation from buggy or hostile extension builds.
  • fix
    Screenshot mutex race eliminated Mutex holder is now assigned synchronously before the promise chain, closing the microtask-race window that could produce spurious MUTEX_BUSY rejections on concurrent screenshots.

Security & AMO compliance

  • feat
    firefox_evaluate requires explicit opt-in Disabled by default. Enable from the Claudezilla popup's new Security section. Documented in SECURITY.md §12 for AMO reviewers; the expression denylist remains as defense-in-depth.
  • refactor
    Watermark refactored to DOM construction Replaced watermarkShadow.innerHTML = ... with explicit <style>.textContent, DOMParser SVG import, and createElement subtree. Clears the UNSAFE_VAR_ASSIGNMENT lint warning. No visual change.
  • chore
    Manifest hygiene strict_min_version bumped 91 → 140 (required by tabs.group + data_collection_permissions); webRequestBlocking permission dropped (no blocking listener wired up); content_scripts.all_frames explicitly set to false.

Worker & website

  • fix
    Donor redirect fixed, D1 binding deferred worker/wrangler.toml previously shipped a placeholder D1 ID and a boot.industries FRONTEND_URL that redirected donors off-brand. Worker now points at claudezilla.com; deferred claudezilla-emails waitlist binding commented out with an activation runbook.
  • feat
    Stripe webhook + idempotency POST /webhook route with HMAC-SHA256 signature verification (5-min replay window, timing-safe comparison) handles checkout.session.completed, idempotent via stripe_event_id UNIQUE. Checkout session creation now sends Idempotency-Key derived from request body hash. donations + schema_version tables added.
  • chore
    Marketing site SEO + CSP Added favicon, robots.txt, sitemap.xml, self-hosted Mozilla install badge (was loading from blog.mozilla.org, contradicting zero-telemetry copy). _headers adds HSTS, CSP, Permissions-Policy, and immutable cache headers.

Tooling

  • chore
    Version centralization + engines field host/ and mcp/ now read version from package.json via import.meta.url; extension reads from browser.runtime.getManifest().version. Added "engines": {"node": ">=18.17"} to both Node packages.
  • test
    Test seed via node --test Coverage for host/protocol.js framing (little-endian, UTF-8, 1 MB cap) and host/ipc.js path validation (null bytes, traversal, UNC). No test framework dependency. Run via pnpm test.

v0.6.5 2026-05-10

Claude Code compatibility — closes the gap with upstream changes 2.1.129 → 2.1.138

Compatibility

  • feat
    Session-scoped loop state Loop state in the native host is now keyed by CLAUDE_CODE_SESSION_ID (Claude Code 2.1.132+). Concurrent Claude Code sessions on the same machine no longer collide on a single /focus loop. Sessions without an ID fall back to a single __default__ bucket, preserving pre-v0.6.5 behavior.
  • fix
    Activation recovery on /clear When Claude Code reloads the MCP server after /clear, the gateway tool was previously the only thing visible, and the agent's first call to a known firefox_* tool would hard-fail with ACTIVATION_REQUIRED. The MCP server now auto-activates the matching category, emits notifications/tools/list_changed, and proceeds with the call transparently.
  • fix
    Stop hook hardening for 2.1.136+ lifecycle plugin/hooks/stop-hook.sh now bounds every socket round-trip with nc -w 2, validates JSON shape before parsing, and forwards the Claude Code session ID. The hook can no longer hang Claude Code's exit path on a stuck socket.
  • chore
    Plugin marketplace metadata plugin/.claude-plugin/plugin.json bumped to v0.2.0 with homepage, bugs, and license fields populated for installation via Claude Code's --plugin-url flag (added in 2.1.129).
v0.6.4 2026-03-31

Supply chain hardening — closes ignore-scripts gap, hardens auth, upgrades MCP SDK

Security Fixes

  • security
    Block dependency lifecycle scripts Added ignore-scripts=true to root .npmrc and per-workspace .npmrc files for mcp/ and worker/. Prevents postinstall hook execution — the primary supply-chain attack vector.
  • security
    Harden install scripts Added --ignore-scripts flag to npm install in install-macos.sh, install-linux.sh, and the windows-test.yml CI workflow. User-facing install paths were previously unprotected.
  • security
    Timing-safe auth comparison Replaced !== string comparison with crypto.timingSafeEqual() for socket auth token validation in the native host.
  • security
    Explicit Content Security Policy Added content_security_policy to extension/manifest.json (defense-in-depth over the MV2 default).

Improvements

  • feat
    Graceful private mode handling firefox_create_window now auto-falls back to non-private mode when Firefox incognito permission isn't granted, instead of hard-failing. Response includes isPrivate, privateFallback, and modeWarning fields so agents always know the actual mode.
  • feat
    New firefox_get_window_mode command Lightweight query for current window state and private mode capability. Pairs with firefox_create_window's new private parameter, which returns a structured MODE_MISMATCH error if the existing shared window's mode conflicts.
  • chore
    Upgraded @modelcontextprotocol/sdk 1.25.2 → 1.29.0 Patches GHSA-345p-7cg4-v4c7 (cross-client data leak via shared server/transport). Claudezilla uses stdio transport (1:1 pipe), so was not exploitable in our architecture, but upgraded for hygiene.

Critical fix: native host fails to start on macOS (and Linux with non-standard node paths)

Bug Fixes

Installer now resolves the absolute node path at install time and writes a host/run.sh wrapper with exec /absolute/path/to/node. Affects both macOS and Linux installers.

v0.6.1 2026-03-22

Linux support + reliability/security audit + lazy tool loading + consent automation

Features

  • feat
    Lazy tool loading — ~6,400 token savings per session firefox_activate gateway tool: at session start, only this single tool (~50 tokens) is exposed instead of all 31 tools (~6,529 tokens). Tools organized into 8 categories (core, inspection, devtools, multiagent, loop, config, diagnose, all). Call firefox_activate() to load the default core category, or pass a specific subset. Server emits notifications/tools/list_changed so Claude Code updates its tool list immediately.
  • feat
    Consent form automation New firefox_handle_consent MCP tool automatically detects and dismisses cookie/GDPR overlays via 4-pass strategy: CMP selectors (Google, OneTrust, Quantcast, Didomi, Cookiebot), text matching ("I agree", "Accept all"), shallow Shadow DOM traversal, and [role="dialog"] ARIA fallback. Can be enabled per-agent via firefox_set_config({ handleConsent: true }) to trigger fire-and-forget after every navigation.
  • feat
    Linux support Portable shebang (#!/usr/bin/env node instead of hardcoded Homebrew path) and install-linux.sh installer that runs npm install in mcp/.

Reliability & Security Audit

  • fix
    Socket listener cleanup (MCP) sendCommandOnce now calls socket.removeAllListeners() + socket.destroy() on every resolve/reject path. Previously, data/error/timeout/close listeners accumulated over many commands causing FD leaks.
  • fix
    Connection limit + per-socket request tracking (host) server.maxConnections = 10 prevents FD exhaustion under DoS. Each socket tracks its pending request IDs in a Set; on socket close, all associated entries are removed from pendingCliRequests to prevent memory leaks on abrupt disconnect.
  • security
    Domain pattern ReDoS prevention checkDomainAllowed now validates each domain pattern before constructing a regex: max 255 chars, only [a-zA-Z0-9*.\-] characters allowed. Pathological wildcard patterns previously could cause catastrophic backtracking.
  • security
    icacls command injection fix (Windows) host/ipc.js replaced exec() shell invocation with execFile('icacls', [...args]) array form, eliminating shell interpretation of file paths containing quotes or special characters.
  • fix
    Screenshot mutex finally block screenshotMutexHolder = null is now inside a finally block, ensuring the mutex is always released even if the screenshot throws. Previously a mid-flight exception would leave the mutex permanently held.
v0.6.0 2026-03-06

Annotated screenshots, domain allowlists, smarter waiting, page state diffing

Features

  • feat
    Annotated screenshots firefox_screenshot with annotate: true overlays numbered badges on every interactive element (buttons, links, inputs, form controls) using Shadow DOM isolation. The response includes a labels map keyed by badge number so agents can reference elements by number in follow-up commands. Badges are injected, the screenshot captured, and badges removed in one atomic sequence — no visual artifacts persist on the page.
  • feat
    Domain allowlist Agents can restrict their own navigation to approved domains via firefox_set_config({ allowedDomains: ["*.example.com", "docs.stripe.com"] }). Supports exact matches and wildcard prefixes. Any createWindow or navigate call to an unapproved domain returns a DOMAIN_BLOCKED error. Opt-in per agent — no global config changes.
  • feat
    Expanded waitFor firefox_wait_for now supports three modes: selector (CSS selector — existing behavior), text (substring match on visible page text), and url (glob match on window.location.href — useful for waiting on redirects or SPA navigation).
  • feat
    Page state diff firefox_diff_page_state takes two snapshots (from firefox_get_page_state) and returns structured diffs: added/removed/changed headings, links, buttons, and form fields. Runs entirely in the MCP server with no extension round-trip needed — useful for verifying that a click or form submission actually changed the page.

Bug Fixes

  • fix
    Orphan tab timeout increased Changed from 2 minutes to 10 minutes. The previous threshold caused false positives during long-running operations (large page screenshots, complex waitFor chains), incorrectly cleaning up active agents' tabs.
  • fix
    Screenshot watermark hidden during capture The Claudezilla watermark and focus glow effects are now hidden during captureVisibleTab and restored after, eliminating visual artifacts in screenshots.
  • fix
    CONTENT_SCRIPT_ERROR false positives JSON, XML, PDF, and binary tabs no longer trigger content script injection errors. The extension now checks the tab's content type before attempting sendMessage and returns a descriptive NON_HTML_TAB error instead.
  • fix
    Network header stripping getNetworkRequests no longer includes raw request/response headers in the payload, reducing response size by ~60% for header-heavy pages.
v0.5.9 2026-03-04

Tab state bug fixes — eliminates stale-tab loops and session nukes

Bug Fixes

  • fix
    Session nuke on empty tabs (CRITICAL) When the last Claudezilla tab was externally closed, getSession() would null the entire session state, requiring a full extension reload to recover. Now throws a targeted NO_TABS error without destroying window state.
  • fix
    Stale-tab infinite loop (SERIOUS) When a tab was closed while a command was in-flight, agents received CONTENT_SCRIPT_UNAVAILABLE and retried forever. Now detects the closed tab and returns TAB_CLOSED with actionable guidance.
  • fix
    Heartbeat timeout during long operations (MODERATE) Heartbeats were only updated at command arrival. Long operations like screenshots or waitFor could exceed the 120s orphan timeout, deleting the agent's tabs mid-operation. Heartbeat now also refreshes immediately before the async operation.
  • fix
    Catch-all scope too broad in getSession (MODERATE) A single try/catch wrapped both window-level and tab-level failures, with both paths resetting session state. Now split: window failure resets state; tab failure throws TAB_UNAVAILABLE without destroying the window.
